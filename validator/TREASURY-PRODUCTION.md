# Native treasury production successor

The treasury successor uses the existing schema-3 production config and V2 measured, prepared, submitted and recovery path. Select `treasury_approval` instead of `owner_recycle_approval`; the two selectors cannot coexist. The approval, proposal, production scope, decision proof, signature and native source commitment have explicit treasury domains. Omitted treasury fields preserve the original owner-recycle wire bytes and hashes.

`TreasuryPolicy` contains only public native custody: the derived multisig account, threshold, canonical sorted signatory AccountIds, and the complete recipient roster. Every recipient binds its UID, hotkey and registration block. It also fixes provider share `1/10`, treasury share `9/10`, cap `32768/65535`, and an optional exact auto-stake destination. A nil destination requires the native storage entry to be absent. The shared `crv4.DeriveNativeMultisigAccount` implements native account derivation; an EVM wallet address cannot substitute for this account.

The multisig and all recipient hotkeys use owner-local hardware custody. Validators receive no treasury private keys, seeds, device paths or signer references. Receiving native incentive requires no recipient signature. Hardware operations are separate from validator admission and never run through these observers.

Admission authenticates the original metadata and storage at one pinned canonical finalized block. Each of at least two recipients must remain an ordinary registered hotkey whose `Owner` is the approved multisig. The multisig must differ from `SubnetOwner`. All registered `OwnedHotkeys[SubnetOwner]` and the explicit `SubnetOwnerHotkey` are excluded. `OwnerHotkeys` in the shared signed carrier records that exact exclusion census, not treasury recipients. Changed ownership, UID, generation, masks or destination refuses the complete row.

The original provider artifact supplies all provider scores and complete validator masks. With two approved treasury recipients the exact unquantized row assigns 45% to each and 10% to providers. Existing quantization, cap and minimum-weight checks still apply; a missing or masked treasury recipient never causes redistribution. Theta remains inside the provider component. A prepared row is not evidence of the final native miner allocation or spendable credit. Independent execution observations must check the then-current owner exclusions, collateral, auto-stake destination and native conservation.

The exported tooling entry points are `ObserveTreasuryAdmission`, `ObserveTreasuryAdmissionAt`, `ObserveTreasuryMeasurementAuthority`, `SealTreasuryMeasurement`, `ReplayTreasuryMeasurement`, `RetainTreasuryApproval` and `BuildTreasuryProductionAuthority`. `DecodeTreasuryApproval` verifies a complete production config. `VerifyTreasuryApproval` and `VerifyTreasuryApprovalPolicy` verify the exact canonical approval bytes against an independently pinned signer and content hash for native accounting consumers; consumers must additionally join the returned signed genesis, netuid, runtime/source, policy and finite activation scope to their execution. These projection APIs grant neither prepared-transaction authority nor signing custody.

An owner-to-treasury transition requires an independently signed advancing policy and drained activation epoch. The previous owner intent must be applied. Historical authority bundles retain the exact original config and approval as read-only authority. Restart, archive intent replay and native source capture select that original authority by its signed sidecar, including the original first epoch and activation metadata. Historical startup anchors at the oldest retained authenticated activation, so an unrelated current metadata outage cannot strand an old liability. Current preparation still requires current authority.

The authored treasury regressions cover actual measured preparation, raw native custody drift, masks and roster refusal, approval and sidecar substitution, submission/restart recovery, original wire compatibility, owner-to-treasury transition, bounded read causes, storage shape, and distinct original activation/decision/successor capture. Source formatting and independent source review are separate from compiler, normal/race body and mutation-control qualification; those executions belong to the designated execution owner.
